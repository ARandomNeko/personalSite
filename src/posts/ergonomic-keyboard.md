I designed and assembled a custom ergonomic keyboard. It is a small hardware project with an unusually close connection to everyday software work: the finished object sits between a person and almost everything they type.

A keyboard's layout is easy to take for granted. Building one makes that layout a set of choices again. Where should the keys sit? Which actions deserve the easiest positions to reach? How much of a familiar arrangement is worth keeping?

## A layout is an interface

The physical arrangement and the logical mapping solve related problems. The arrangement determines where a finger needs to move; the mapping determines which action lives at that position. A compact arrangement can reduce the number of physical keys while asking the user to remember more combinations. A familiar arrangement can be easier to pick up while leaving less room to rethink those movements.

Those tradeoffs are the interesting part of a custom keyboard. There isn't a single layout that follows automatically from the word “ergonomic.” The design has to be considered in relation to its user and the tasks they repeat.

## From a design to an object

Assembly gives a keyboard design a physical test. A drawing can show spacing and shape, but the assembled object is what someone actually types on. The useful questions become concrete: can a key be reached comfortably, is its action easy to remember, and does the arrangement make sense during an ordinary stretch of work?

This project sits alongside my software work as another kind of interface design. Instead of only choosing what appears on a screen, it means choosing the object used to interact with that screen. The result was a custom keyboard I had taken through both design and assembly.
